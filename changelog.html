Changelog

What changes for people using Linkwright for Jira, newest first.

1 October 2026 — version 2.7

  • Refresh now repairs branches too. Jira can drop a branch from an issue while keeping it stored; resending it does not bring it back. A full send now deletes the branches Jira holds, waits until Jira confirms the deletion, then creates them again — the way commits were already repaired. Measured on our test site: 30 branches and 20 pull requests back on their issue.

1 October 2026 — version 2.6

  • Older commits on feature branches are caught up. On the first read after a repository is attached, and on each Refresh, the app reads the commits that up to 20 branches it has not seen yet hold beyond the default branch. Before, only the default branch’s history was caught up.

1 October 2026 — version 2.5

  • New repositories appear within 10 minutes of being added to the GitHub App, instead of up to an hour.
  • Bursts of activity are handled faster. A push updating 30 branches now reaches Jira in about a minute; before, the burst could saturate the app’s storage, and the last links took three to four minutes to arrive.
  • Guided setup. The administration page shows a checklist of the setup steps, computed from what the site actually holds, with a link to install the GitHub App.
  • Suggested repositories. A project’s settings page lists first the repositories whose recent commits cite that project, with a button to attach them all.
  • Clearer refusals. When the person connecting a GitHub organization is not one of its owners, the page says so and explains who can do it.
  • Sync health counts attached repositories only. A repository no project uses is no longer reported as “never synced”.

30 September 2026 — version 2.1

  • Disconnecting a GitHub organization detaches all its repositories and removes their webhooks and Development panel entries; it can be safely retried.
  • Attaching or detaching a project on a repository shared by several projects updates the issues of that project only.
  • Failed removals are retried automatically, a few repositories at a time.
  • A repository detached from its last project and attached again sends its history to Jira again.

September 2026 — first versions

  • Commits, branches, pull requests with reviews, and deployments in Jira’s native Development panel, so JQL, boards and Automation work as usual.
  • A sync state for every repository, with its last webhook and its last successful check, and a Refresh button.
  • A check five minutes after sending that Jira kept the links of a full send, with repair.
  • Repositories scoped per Jira project, connected by an owner of the GitHub organization.
  • English and French interface.
