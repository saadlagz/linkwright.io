  2. +0 s Un commit qui cite CHK-5 est poussé sur GitHub.
  3. +5,7 s Linkwright le relie à CHK-5. À +57 s, le panneau Développement de Jira compte deux commits.

Le pont entre GitHub et Jira, c’est la partie que tout le monde subit.

La plainte qui revient le plus souvent n’est pas une fonction manquante. C’est que tous les indicateurs disent « connecté », que rien ne se lie, et que rien ne dit pourquoi.

J’ai lu un par un 279 avis négatifs des deux connecteurs officiels avant d’écrire une ligne de code. Linkwright est construit autour de cette seule phrase.

Le coût n’est pas vraiment pour le développeur. C’est que l’état des tickets cesse d’être une image fiable de l’avancement — et on le découvre au point du matin, ou devant un client.

Ce que ça fait

Savoir ce qui est à jour, avant d’en rendre compte

Chaque dépôt affiche son dernier webhook, sa dernière lecture complète et un état clair : À jour, Pas à jour, Quota épuisé, En échec, Non autorisé ou Webhook en panne, avec la raison. Un clic le relit depuis GitHub.

Vos tableaux, votre JQL et Automation continuent de marcher

Commits, branches, pull requests avec leurs approbations et déploiements arrivent dans le panneau Développement natif de Jira : tableaux, JQL et Automation marchent exactement comme avec l’intégration d’Atlassian. Un déploiement est relié à chaque commit qu’il livre, pas seulement au dernier.

Personne ne voit un dépôt qu’il ne devrait pas voir

Un dépôt ne se relie qu’aux tickets des projets Jira auxquels il est rattaché. Associer une organisation GitHub demande l’un de ses propriétaires : personne ne peut exposer dans Jira des dépôts privés qu’il ne voit pas lui-même sur GitHub.

Les webhooks d’abord. Les relectures, seulement pour rattraper ce qu’ils ont manqué.

Une équipe de trois mille dépôts dispose d’environ quatre requêtes à l’API GitHub par dépôt et par heure. L’interrogation périodique ne tient pas dans ce budget : c’est exactement pour ça que les connecteurs qui en dépendent prennent du retard.

  1. GitHub envoie l’événement

    Il arrive sur votre site Jira au moment où il se produit, par un webhook signé. Les webhooks ne consomment aucun quota d’API GitHub.

  2. Les clés de tickets sont repérées

    Dans les noms de branches, les messages de commit et les titres de pull requests, uniquement pour les projets auxquels ce dépôt est rattaché.

  3. Jira est mis à jour

    Directement dans le panneau Développement natif : tout ce que vous avez déjà construit dessus continue de marcher.

  4. Une relecture périodique rattrape le reste

    Revérifier des données inchangées ne coûte rien. Ce qu’aucun webhook n’a annoncé vous est signalé, pas caché.

Linkwright tourne entièrement sur Atlassian Forge. Vos données restent dans le stockage de votre propre site Jira, je n’ai aucun serveur nulle part, et aucune donnée Jira n’est jamais envoyée à GitHub. Lire la politique de sécurité (en anglais)

Ce que ça ne fait pas encore

Écrit ici plutôt que découvert plus tard, parce que c’est tout l’objet du produit.

GitHub.com seulement
GitLab, y compris auto-hébergé, est prévu dans une version ultérieure.
Rattrapage partiel de l’activité ancienne
Au rattachement d’un dépôt, les commits récents de la branche principale, les pull requests et les branches récentes sont reliés. Un commit poussé plus tôt sur une autre branche ne l’est pas.
Relectures et déploiements arrivent seulement par webhook
La relecture périodique ne les rattrape pas.
Pas de certification
Ni SOC 2, ni ISO 27001. L’outil est fait pour des équipes de 20 à 200 personnes en libre-service, pas pour les procédures d’achat des grands comptes.

Les questions que les équipes posent d’abord

Réponses courtes. La documentation donne les longues.

Quels hébergeurs Git sont pris en charge ?
GitHub.com, par une GitHub App installée sur votre compte ou votre organisation. GitHub Enterprise Server et GitLab ne sont pas pris en charge dans cette version.
Les Smart Commits, le JQL et Automation marchent-ils toujours ?
Oui. Linkwright remplit le panneau Développement de Jira lui-même : development[commits] en JQL, les badges des tableaux, les Smart Commits et les transitions automatiques se comportent comme avec l’intégration d’Atlassian.
Qu’est-ce qui sort de notre site Jira ?
Rien n’est envoyé à GitHub. Linkwright lit GitHub et écrit dans votre site Jira, et tourne entièrement sur Atlassian Forge : aucun serveur à moi entre les deux. Détails dans la politique de sécurité.
Qui voit quels dépôts ?
Un dépôt n’alimente que les projets Jira auxquels il est rattaché, et seul un propriétaire de l’organisation GitHub peut l’associer à votre site. Personne ne voit dans Jira un dépôt privé qu’il ne pourrait pas voir sur GitHub.
Que se passe-t-il quand un lien casse ?
L’état du dépôt passe à Quota épuisé, En échec, Non autorisé ou Webhook en panne, avec la raison et l’heure du dernier succès. Rafraîchir le relit depuis GitHub.
Qui est derrière, et en combien de temps le support répond-il ?
Un développeur indépendant, immatriculé en France. Première réponse sous deux jours ouvrés, à saad@linkwright.io, en français ou en anglais.
